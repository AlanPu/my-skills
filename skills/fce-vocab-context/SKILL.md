# FCE 词汇实战示范文生成器

## 技能文件结构

```
fce-vocab-context/
├── SKILL.md                    ← 你正在读的运行流程（每次必读）
├── references/
│   ├── genres.md               ← 体裁库：9 个体裁的执行卡片（定下体裁后必读对应卡片）
│   └── state.json              ← 交付台账：已用体裁 + 已用词条（抽签与去重的依据）
└── assets/
    ├── template.html           ← 页面模板（复制后替换内容，不要重新设计版式）
    ├── pick.py                 ← 随机抽体裁 + 打印词表黑名单
    └── export_pdf.py           ← 把学习页导出成适合打印的 PDF
```

## 解决的问题

用户背了 FCE 单词但记不住、写作文不会用。根因是**没有真实语境 + 只记中文意思不记搭配**。
所以输出物不是词表，而是「**语境 + 搭配 + 对比改写**」三合一的学习页。

## 交付物形态

单个自包含 HTML 文件（无外部依赖，离线可开），写入 `outputs/` 目录，用 `present_files` 呈现。
模板：`assets/template.html`（直接复制后改内容，不要重新设计版式）。

页面结构（6 个区块，顺序固定）：

| # | 区块 | 作用 |
|---|---|---|
| ① | 英文原文 | 高亮词可点击，右侧出详情卡 |
| ② | 中文译文 | 画线与①一一对应，同样是可点击的 `.hl` |
| ③ | 平淡句 → 高级句 | **最能打动用户**。人物类用用户作文原句；非人物类改用「考场常见低分句」（very beautiful 那类零信息句）|
| ④ | 写作迁移 | 按体裁换表单，见下 |
| ⑤ | 词汇精讲表 | 词条 / 音标 / 搭配 / 例句，点行同步高亮原文 |
| ⑥ | 高频易错点 | 本篇新词的专属坑（不可数名词、lie/lay、worth doing…）|

右栏：详情卡（sticky）+ 图例 + 「怎么用这一页」。**产出 3 篇起加一张「路线图」卡**，
列出已发篇目（体裁 / 人物 / 词数）+ 已覆盖的题型 + 下一步建议，让用户看到累积价值。

## 打印 / 导出 PDF（已内建在模板里）

**这一块不要在新页面里重做，`assets/template.html` 已经带好了。** 复制模板即自动拥有：

- `@page{ size:A4; margin:13mm 12mm 15mm }` —— 输出固定 A4。
- 一整套 `@media print`：切浅色主题（所有 CSS 变量在 print 下被重定义）、
  隐藏 `.toolbar` 与 `aside.col-right`、表格转白底深字、`thead{display:table-header-group}` 让跨页表头重复、
  对 `.upg-row` / `#printAppendix .pe` / `tr` 做 `break-inside:avoid` 防止条目被拦腰截断。
- **`#printAppendix`（class `print-only`）** —— 屏幕上 `display:none`，打印时展开。
  由末尾的 `buildPrintAppendix()` 从 `V` / `ORDER` 生成**全部 12 个词条**的详解。
  这是关键设计：屏幕上详情卡一次只显示 1 个词（要点才出），纸面上没有点击，必须一次铺开。
- **实线 / 虚线双编码**：打印时核心词用 `border-bottom:2px solid`，高级搭配用 `2px dashed`，
  配合 `print-legend` 图例。目的是**黑白复印后两类词仍然分得开** —— 只靠颜色是不行的。
- 工具栏按钮 `#btnPrint` → `window.print()`。用户想手动打印时走这条路，效果与脚本一致。

导出命令（不依赖浏览器界面，可批量、可重复）：

```bash
python3 assets/export_pdf.py <页面.html>          # 单文件 → 同目录同名 .pdf
python3 assets/export_pdf.py <目录>               # 批量该目录下所有 *.html
python3 assets/export_pdf.py --check <目录>       # 只体检哪些页面缺打印支持
```

⚠️ **两个必须知道的坑（脚本已处理，但出问题时要会判断）**：
1. 浏览器已在运行时，headless 调用会被转交给现有实例、**静默不产出且退出码为 0**。
   脚本用独立的 `--user-data-dir` 临时 profile 规避。
2. 浏览器会往沙箱外写（Crashpad 转储、macOS 登录钥匙串），受限沙箱里会被拦。
   脚本已加 `--disable-breakpad` / `--crash-dumps-dir` / `--use-mock-keychain` 等开关压到最低，
   **但仍可能需要非沙箱运行** —— 这是浏览器本身的限制，不是脚本能绕过的。
   失败时不要反复重试，直接告知用户需要用非沙箱方式执行。
3. 导完必须校验：文件头应为 `%PDF-`、字节数非 0、页数合理（一页学习页正常 5–8 页）。
   脚本内置了这三项校验并会打印结果。

### 第 ③ ④ 区块随体裁变 —— 查体裁库

**`references/genres.md` 是体裁库，9 个体裁各有一张卡片**，卡片里写死了这个体裁的
FCE 题型 / 待用候选词 / 第 ③ 区块形式 / 第 ④ 表单列名与行名 / 段落骨架 / 必须抄进页面的铁律 / 易错点方向。

抽到哪个体裁，就照哪张卡执行 —— **不要临场自己设计第 ④ 表单的列名和行名**，
卡片里的行名（如 place 的「交代位置 / 第一印象 / 具体描写…」）是反复验证过好用的。

- 人物类（biography）：第 ③ 用用户作文原句；有多种篇目时第 ④ 升级为跨篇对照表。
- 其他体裁：第 ③ 用「考场常见低分句」（very beautiful 那类零信息句）。
- 每个体裁的卡片末尾都有一组「铁律」，**必须挑 2–3 条抄进页面第 ④ 区块下方**，
  这是用户真正会反复回看的部分。

**多篇之间的硬规则：词表零重叠。** 交付后用脚本比对各篇的 `V` key 集合与 `term` 集合，
两两交集必须为空，并在页脚注明「合计 N 个高频表达」。不重叠才能累积成表达库；重复出现等于白做功。

## 硬性写作要求

- **词数 90–120 词**。写完必须用脚本校验词数，不要凭感觉。
- **FCE 词条 10–13 个**，分两类：
  - `A` 类（蓝色）= FCE 核心词，可独立记忆的实词/动词（remarkable, dedicate, tirelessly, extraordinary, persistence, contribution, award…）
  - `B` 类（黄色）= 高级搭配/句型/介词短语（from an early age, be appointed to, pay off, in recognition of, a source of inspiration…）
- 高亮密度约 20–25%。**在页脚必须注明这是「高密度展示文」，真实写作一段用 2–3 个即可**——否则用户会以为范文就该这么堆。
- **体裁必须轮换，不要连做同一类**。用户会明确抗议（「不要都是人物介绍」）。
  体裁库和已用清单见 `references/genres.md` + `references/state.json`，
  **交付前必须先跑 `assets/pick.py` 抽签**，不要凭手感挑。
- 人物类选中国知名人物（屠呦呦、袁隆平、张桂梅…），用户有背景知识，注意力能全放在语言上。
- 地点类选**不要太热门**的地方（元阳梯田 > 长城），既有画面又可写「冷门」的高级感。
- 已交付篇目不要记在这里（会忘同步），**一律以 `references/state.json` 为准**。

## 词条数据 schema

模板里 JS 对象 `V` 的每个条目必须齐这些字段，缺一个详情卡就会显得空：

```js
key:{
  type:'A'|'B',
  pos:'adj.'|'n.'|'动词（被动）'|'介词短语'|'动词短语（不及物）',
  term:'显示在详情卡标题的词条',
  ipa:'/rɪˈmɑːkəbl/',
  zh:'中文释义，多义用分号',
  usage:'用法说明：词族（名/动/形/副）、句型、正式度',
  colloc:['搭配1','搭配2','搭配3'],   // 3–4 条，这是记忆的核心
  ex:'英文例句（原文句或另造一句）',
  exzh:'例句中译',
  warn:'❌ 错 → ✅ 对（介词/搭配硬伤）',
  swap:'平庸表达 → 高级表达'
}
```

四张映射表要同步更新，否则会出错：`V`、`ORDER`（表格行序）、`SHORT`（表格里的中文）、`CL`（表格里的搭配）。
**易错点必须真的易错**，而且要对准本篇体裁 —— 每个体裁卡片的最后一行给了「易错点方向」，
照那个方向写 6 条，别每次都写同一批介词坑（用户会看出来在复用）。
已积累的经典方向：不可数名词（scenery）、形近词（wander/wonder、breath/breathe）、
不规则动词（overcome–overcame）、worth 接 doing 不接 to do、dedicate/commit to doing、be awarded 漏 be。

## 工作流

0. **抽签定体裁**：跑 `assets/pick.py`。它会排除已用体裁、随机抽一个、并打印必须避开的旧词条黑名单。
   - `--peek` 看体裁库全貌与已用/未用状态；`--genre <id>` 指定体裁；`--avoid` 只拿黑名单。
   - 抽到后打开 `references/genres.md`，照对应的 `## G? <id> —— …` 卡片执行。
   - 用户明确指定了体裁或主题 → 遵从用户，但仍要跑 `--avoid`。
1. 读用户上传的作文截图（如有）——**必须从里面摘 4–5 个原句**做第 ③ 区块。
   用户原句要原样保留（含 `he still work very hard` 这类语法错误，这正是教学价值所在，不要偷偷改掉）。
   没有用户作文时，第 ③ 区块用「考场常见低分句」。
2. 按体裁卡片里的「待用候选词」拟定 12 个 A/B 词条清单（先定词，再写文，不要反过来），
   并逐个与 `pick.py` 给的黑名单核对，确保零重叠。
3. 写 90–120 词短文，把词条自然嵌进去。
4. 写中译，逐句对齐高亮。
5. 复制 `assets/template.html`，替换 passage / 中译 / `V` / 四张映射表 / 第 ③④⑥ 区块（④ 的表单列名行名抄体裁卡片）。
6. 校验（固定三步，缺一不可）：
   - **词数**：`python3` 提取 `id="en"` 的 `textContent` 去标签后 split。
     ⚠️ 坑：正文若用了 `&mdash;`，`split(' ')` 会把破折号单独算成一个词 —— 用 `re.sub(r'[\u2014\u2013]','',t)` 剔除后再数。
     **页面的词数不要手写死**，在模板里放一个 `<span id="wc">` 并用 JS 自动统计（token 需含字母或数字才计数），
     页脚再放一个 `id="wc2"`。手写数字迟早和正文对不上。
   - **三方对齐**：提取所有 `.hl` 的 `data-v`，逐一确认都能在 `V` 里找到；再比对 `ORDER` 与 `V` 的 key 集合互为子集（防止加了词忘进表）。
     多篇时额外比对**所有已交付篇目**的 `V` key / `term` 集合两两交集为空。
   - **语法**：抽出 `<script>` 内容跑 `node --check`；顺手 `grep -n '\*\*' <file>` 扫 Markdown 残留。
7. **回填台账**：把新篇目追加到 `references/state.json` 的 `delivered` 数组
   （n / title / file / genre / subject / words / coreWords / phrases / terms），
   并在页面的「路线图」卡里补一行。**漏了这步，下次抽签就会重复体裁和词表。**
8. `present_files` 呈现，并在正文里给出核心信息（体裁、词数、词条数、最有价值的那几条改写）。
9. **（可选）导出打印版 PDF**：用户提「打印」「PDF」「纸质版」时，跑
   `python3 assets/export_pdf.py <新页面.html>`，把生成的 `.pdf` 一并 `present_files`。
   导完自检页数（5–8 页为正常），并把 PDF 路径告诉用户。

## 设计约束

- 深色主题（用户 IDE 为 dark）。CSS 变量已定义在模板 `:root`，改主题只动变量。
- `--a` 蓝 `#79c0ff` = 核心词；`--b` 琥珀 `#ffd479` = 高级搭配。**这个颜色分工不要变**，用户已建立认知。
- 每个 `.hl` 必须有 `data-v="<V里的key>"`，点击事件依赖它。
- 不要引 CDN 字体/框架，必须离线可开。
- ⚠️ **`V` 里的 `usage` / `warn` 等字段是用 innerHTML 注入的，所以里面必须写真 HTML 标签，不能写 Markdown 语法。**
  踩过一次：`**永远不可数**` 在页面上原样显示成星号。要强调就写 `<b style="color:#79c0ff">…</b>`，
  或者用中文引号「」。交付前 `grep -n '\*\*' <file>` 扫一遍。
- 中文引号统一用「」，英文例句里的撇号在单引号 JS 字符串中要转义成 `\u2019`（否则语法报错）。
